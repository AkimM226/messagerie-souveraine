Messagerie souveraine de l'administration

Équipe : [NOM DE L'ÉQUIPE] · [UNIVERSITÉ] · Dépôt : github.com/AkimM226/messagerie-souveraine

1. Concept

Une messagerie instantanée (messages, groupes, fichiers) aussi simple que les applications grand public, mais réservée aux agents publics enrôlés et entièrement hébergée sur l'infrastructure de l'État. Le serveur transporte et stocke des messages qu'il ne peut pas lire : seuls les appareils des agents détiennent les clés. Aucune donnée ne quitte le pays, aucun service tiers n'est nécessaire, et l'installation tient en une commande.

2. Architecture

Navigateur ou mobile de l'agent (Element) ── chiffre / déchiffre ──► Caddy (point d'entrée HTTPS) ├─► Synapse (serveur Matrix) ─► PostgreSQL │ + module « classification » (innovation) └─► Keycloak (annuaire des agents, 2FA, rôles)
  • Element (client) chiffre chaque message et chaque fichier avant l'envoi.
  • Synapse (serveur) relaie et stocke des données déjà chiffrées ; fédération désactivée : il ne parle à aucun autre serveur.
  • Keycloak est la seule porte d'entrée : mot de passe + code TOTP, rôles, désactivation. Synapse n'a aucun mot de passe local.
  • Docker Compose : docker compose up -d démarre les cinq services, sans dépendance externe.

3. Protocole de chiffrement retenu : Matrix (Olm / Megolm)

Olm (double ratchet, comme Signal) établit un canal chiffré entre deux appareils ; Megolm chiffre les messages de groupe avec une clé de session partagée via Olm à chaque appareil membre. Quand un membre quitte le groupe (ou est révoqué), les autres appareils génèrent une nouvelle clé : il ne peut plus lire les messages suivants. L'implémentation utilisée est celle du client Element : vodozemac, implémentation Rust d'Olm/Megolm auditée, via matrix-sdk-crypto. L'équipe n'a écrit aucune ligne de cryptographie.

5. Niveau d'engagement open source : « Étendre et adapter »

Nous assemblons des briques éprouvées et les adaptons aux exigences de l'administration : configuration durcie (aucun service tiers, métadonnées réduites), enrôlement obligatoire par rôle, outil de révocation et module serveur original de classification. Contribution prévue : traduction de l'interface d'Element en langue nationale (mooré) soumise au projet d'origine.

6. Fonctionnalités innovantes

  • Salons classifiés à expiration automatique. Un agent nomme son salon [CONFIDENTIEL] … ou [DIFFUSION RESTREINTE] …. Le serveur, sans jamais lire les messages, les supprime automatiquement de tous les appareils au-delà de la durée fixée par le niveau (ex. 24 h / 7 jours), interdit le déclassement du salon et son ouverture au public. Une conversation sensible ne laisse ainsi aucune trace durable.
  • Révocation en une commande (docker compose run --rm admin revoquer <agent>) : compte désactivé, toutes les sessions fermées, tous les appareils déconnectés, retrait de tous les groupes — en moins de 3 secondes.
  • Annuaire des agents : tout agent enrôlé peut trouver un collègue ; aucun compte extérieur n'y figure.
