Messagerie souveraine de l'administration

Équipe : FasoCrypt · Université Aube Nouvelle, Bobo-Dioulasso · Dépôt : github.com/AkimM226/messagerie-souveraine

1. Concept

Une messagerie instantanée (messages, groupes, fichiers) aussi simple que les applications grand public, mais réservée aux agents publics enrôlés et entièrement hébergée sur l'infrastructure de l'État. Le serveur transporte et stocke des messages qu'il ne peut pas lire : seuls les appareils des agents détiennent les clés. Aucune donnée ne quitte le pays, aucun service tiers n'est nécessaire, et l'installation tient en une commande.

2. Architecture

Navigateur de l'agent : Element (chiffre / déchiffre) + widget « circuit administratif » │ HTTPS ▼ Caddy (point d'entrée) ─┬─► Synapse (serveur Matrix) ─► PostgreSQL │ + modules « annuaire » et « classification » └─► Keycloak (agents enrôlés, 2FA, rôles, journal)
  • Element (client) chiffre chaque message et chaque fichier avant l'envoi.
  • Synapse (serveur) relaie et stocke des données déjà chiffrées ; fédération désactivée : il ne parle à aucun autre serveur.
  • Keycloak est la seule porte d'entrée : mot de passe + code TOTP, rôles, désactivation. Synapse n'a aucun mot de passe local et relit l'annuaire toutes les 5 s (révocations, noms affichés, responsables).
  • Docker Compose : docker compose up -d démarre les cinq services, sans dépendance externe.

3. Protocole de chiffrement retenu : Matrix (Olm / Megolm)

Olm (double ratchet, comme Signal) établit un canal chiffré entre deux appareils ; Megolm chiffre les messages de groupe avec une clé de session partagée via Olm à chaque appareil membre. Quand un membre quitte le groupe (ou est révoqué), les autres appareils génèrent une nouvelle clé : il ne peut plus lire les messages suivants. L'implémentation utilisée est celle du client Element : vodozemac, implémentation Rust d'Olm/Megolm auditée, via matrix-sdk-crypto. L'équipe n'a écrit aucune ligne de cryptographie.

5. Niveau d'engagement open source : « Étendre et adapter »

Nous assemblons des briques éprouvées et les adaptons aux exigences de l'administration : configuration durcie (aucun service tiers, métadonnées réduites), enrôlement obligatoire par rôle, et code original : deux modules Synapse (annuaire et révocation, classification) et le widget du circuit administratif.

6. Fonctionnalités innovantes

  • Circuit administratif chiffré. Un responsable émet une instruction de service, une note, une convocation ou une demande d'action (priorité, échéance, accusé demandé). Chaque destinataire répond d'un clic : Reçu, Pris connaissance, En cours, Exécuté ou Demande de clarification ; l'émetteur suit les réponses dans un tableau. Tout est chiffré de bout en bout par Element : le serveur ne distingue même pas une instruction d'un message ordinaire.
  • Classification. [DIFFUSION RESTREINTE] ou [CONFIDENTIEL] en tête du nom d'un salon (réservé aux responsables) : expiration automatique des messages sur tous les appareils, ni déclassement ni ouverture au public, filigrane nominatif sur les communications confidentielles.
  • Annuaire institutionnel et révocation centralisée. L'annuaire Keycloak, tenu par les administrateurs, fait foi : nom, fonction, direction et ministère affichés et recherchables ; désactiver un agent dans la console coupe toutes ses sessions en moins de 5 s et renouvelle les clés de ses groupes.
